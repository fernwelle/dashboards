Dashboard System — Reference

private static-file pipeline · git → mac mini → caddy → tailscale · tailnet only

00What this is

A private place to host HTML files (meal plans, productivity boards, project pages, PDFs, images) and reach them from any device on the tailnet. Files live in a git repo; pushing to the repo makes them live within ~60 seconds. Reachable only by your own Tailscale devices — no public access.

Live URL: https://server.lion-canopus.ts.net

Key split: the Mac holds a read-write key and pushes. The Mini holds a read-only deploy key and only pulls. A server never holds a write-capable key — that's deliberate.

02Daily workflow — add / update files

All of this happens on the Mac. Never touch the Mini for normal use.

cd ~/projects/dashboards
# move/copy your .html (or .pdf / .png) files into this folder first
git add -A
git commit -m "add diet and workout dashboards"
git push
  • Use git add -A (catches additions, edits, and deletions).
  • One commit + push can carry many files — no need to push per file.
  • The filename is the label in the index. Name descriptively, lowercase-with-hyphens: personal-workout-zone2.html, not doc1.html.
  • Flat structure with category prefixes (personal-, kripa-, finance-) auto-groups files alphabetically without folders.

To delete: rm file.html then git add -A && git commit -m "remove x" && git push. Gone from the live index on next pull; still recoverable from git history.

04Config reference (on the Mini)

~/stacks/dashboards/Caddyfile

:8080 {
    root * /srv/dashboards
    file_server {
        browse /srv/dashboards/browse.html
        hide .git
    }
    encode gzip
}

~/dashboards-pull.sh

#!/bin/bash
cd ~/dashboards && /usr/bin/git pull --quiet
Caddyfile gotcha: browse with a template path must live inside a file_server { } block. Putting it on one line (file_server browse /path) makes Caddy crash-loop with a "wrong argument count" parse error.

05Troubleshooting

SymptomCheck / fix
Page won't load (name)
NXDOMAIN		Device can't resolve the name. Toggle Tailscale off → on on that device to refresh MagicDNS. Confirm MagicDNS is enabled in admin console (login.tailscale.com → DNS).
SSL error on the IP
ERR_SSL_PROTOCOL_ERROR		Expected. The cert is issued for the name, not the bare IP. Use the name, not the IP, over HTTPS.
Page won't load (all)Confirm Tailscale is connected on the device, and that the Mini is online: tailscale status on the Mini.
Caddy down / crash-loopdocker ps | grep caddy → want Up, not Restarting. If looping: cd ~/stacks/dashboards && docker compose logs caddy --tail 20 to see the error.
Files not appearingDid the Mini pull? Force it: cd ~/dashboards && git pull. Check the timer is loaded: launchctl list | grep dashboards → want a line ending com.fernwelle.dashboards-pull with exit code 0.
Is Caddy serving at all?On the Mini: curl -I http://127.0.0.1:8080 → want HTTP/1.1 200 OK. If yes, problem is Tailscale/DNS side, not Caddy.
Serve mapping losttailscale serve status → should show the name → http://127.0.0.1:8080. Re-add: tailscale serve --bg 8080.

06Common admin commands (Mini)

# restart Caddy after a Caddyfile change
cd ~/stacks/dashboards && docker compose restart

# recreate Caddy after a compose change
cd ~/stacks/dashboards && docker compose up -d

# force a pull right now (don't wait for the timer)
cd ~/dashboards && git pull

# reload the auto-pull timer
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.fernwelle.dashboards-pull.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.fernwelle.dashboards-pull.plist

# check what Serve is exposing
tailscale serve status

07Good to know

  • Not for sharing. Tailnet-only — you can't send a link to a third party. For that, use Nextcloud / Drive.
  • Not your vault. This is a working dashboard, not a backup for irreplaceable originals. Keep critical scans/deeds/records in durable storage (Nextcloud + a second copy).
  • Binaries: a few PDFs/images are fine. Many large files bloat the git repo (it keeps every version forever). If it gets media-heavy, serve those from a folder outside git.
  • The index is generated live by Caddy on each load from browse.html — nothing to rebuild. Add a file, it appears; remove it, it's gone.
